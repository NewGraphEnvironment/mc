## Findings

- **[severity: bug]** R/mc_md_draft.R:46 (and R/mc_md_send.R:51) — `mc_md_meta(path)$draft_id` partial-matches. With no `draft_id:` line but a sibling key such as `draft_id_old: "r-OTHER"` (a natural way to "start a fresh draft" while keeping a record of the old id), `$` returns `"r-OTHER"`, and `mc_md_draft()` hands it to `mc_draft(draft_id = )`, which PUTs over that other draft in Gmail, replacing its content. Gmail returns the same id, so `identical(new_id, file_id)` is TRUE and nothing is recorded: every later run overwrites `r-OTHER` again. Reproduced offline (mock of `mc_draft`, frontmatter `to`, `subject`, `draft_id_old: "r-OTHER"`): `draft_id passed to mc_draft: r-OTHER`, file unchanged. `frontmatter_set()` itself is unaffected (its `^draft_id:` pattern needs the colon). Fix: `mc_md_meta(path)[["draft_id"]]` in both places. The mc_md_send one only drives a message, but read both with `[[`, since the two readers of the same key should agree. The `meta$thread_id`/`meta$cc`/`meta$from` reads in `md_dispatch_args()` are pre-existing with the same shape; this branch widens `thread_id`'s reach, because a draft now goes into the thread a `thread_id_*` sibling names.
  - **Rule:** code-check-r.md "`$` on a list partial-matches, so a longer sibling key answers for a missing one"
