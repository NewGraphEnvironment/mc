## Findings

- **[severity: bug]** R/mc_md_render.R:163 and R/mc_md_render.R:199 — `style_tag()` and `inject_link_target()` scan with a **name-specific** pattern (`start_tag_regex("td")`, `start_tag_regex("a")`), so they never consume the other tags. The scanner walks through every other tag's quoted attribute values as if they were text, and reads markup inside them. That differs from an HTML reader, which tokenizes every tag. `cid_walk()` is clean because it scans with `start_tag_regex()` (any name) and so consumes every tag; the two name-specific callers never got that. kableExtra writes `title=` and `data-content=` unescaped, which is exactly the producer the round-3 fix cites. Reproduced through `mc_compose()`:
  - `kableExtra::cell_spec("1", popover = spec_popover(content = "see <a href='https://x.org'>site</a>"))` gives valid HTML, and its cell reads `" 1 "` in `xml2::read_html`. After `mc_compose()`, `inject_link_target()` has inserted `target="_blank" rel="noopener noreferrer"` with double quotes inside the double-quoted `data-content`. That ends the value and then the `<span>`, so the cell the recipient sees reads `" site\">1 "`. **This is a regression:** `inject_link_target` is new on this branch, and main does not have it.
  - `cell_spec("1", tooltip = "a <td> b")` gives a cell reading `" 1 "`. After `mc_compose()` it reads `"  b\">1 "`, because `style_tag("td")` writes `style="..."` into the title. Main's `gsub('<td>', …, fixed = TRUE)` had the same defect, so this one predates the branch, but it is the same mechanism.
  - The same gap reaches the new skip: a `<!--`, `<script` or `<style` inside another tag's value starts a skip region. Every real `<td>` and `<a>` up to the next `-->` (or the matching close tag) is then left unstyled and keeps no new-tab target. Probe: `<span title="a <!-- b"></span><td>1</td><span title="-->">` leaves the `<td>` untouched.
  - Fix: scan with `start_tag_regex()` (any name), as `cid_walk()` does, and select by name inside the callback (the tag's name is the `^<[A-Za-z][A-Za-z0-9-]*` prefix `tag_attrs()` already strips, compared case-insensitively). Then all three scans consume tags identically.
  - **Rule:** code-check.md "A fix lands in one of two callers that share a harness"

- **[severity: fragile]** R/mc_preview.R:71, with the fix at R/mc_deliver.R:374 — the round-3 invalid-UTF-8 handling went into `check_inline_images()`, not into `cid_walk()`, the walker both consumers share. Given a body that is not valid UTF-8 (for example a latin1 `sig_path`, which `mc_md_render()` appends), `preview_inline_images()` makes `gregexpr()` warn `input string 1 is invalid UTF-8` and rewrites nothing. The preview then shows broken images for a message the send check accepts and sends correctly. Reproduced: `preview_inline_images(paste0('<p>caf', "\xe9", '</p><img src="cid:logo">'), list(logo = "DESCRIPTION"))` gives the warning and no rewrite. This is the preview/send disagreement that round 2 consolidated away, reopened by putting the fix in one caller. Doing the escape inside `cid_walk()` would not work for the preview: the escaped string cannot be returned as the HTML. The walker needs a byte-safe scan (for example `useBytes = TRUE` on the gregexpr, with positions kept in bytes), or the preview needs its own escape-then-map step.
  - **Rule:** code-check.md "A fix lands in one of two callers that share a harness"

- **[severity: fragile]** R/mc_deliver.R:374 — `iconv(html, "UTF-8", "UTF-8", sub = "byte")` replaces each bad byte with the literal text `<e9>`, which puts `<` and `>` into the string the tag grammar then parses. Inside an unquoted value, the inserted `>` ends the tag, and every attribute after it, a `src=cid:` included, becomes text. Probe: `check_inline_images(NULL, "<img alt=Caf\xe9 src=cid:logo>")` returns `NULL` instead of erroring. So a send that should be refused, because it would show a broken image, goes ahead. The producer is a hand-written or Word/Outlook-saved signature or HTML part in windows-1252: Word writes unquoted attribute values. It needs a non-ASCII character in an unquoted value before the `src`, so it is rare. `sub = "?"` (or any replacement without markup characters) closes it.
  - **Rule:** code-check.md "A guard that fails toward pass"
